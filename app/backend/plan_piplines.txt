 ### 1. Этап до ИИ (Pre-processing & Routing)

  • Пайплайн управления памятью (Memory / Context Management)
      • Для чего: Модель ничего не помнит о прошлых сообщениях. Если ты спросишь "А как его звали?", она не поймет, о
      ком речь.
      • Что делает: Перед отправкой запроса к ИИ, этот пайплайн обращается к твоей базе данных (get_chat_messages),
      достает последние N сообщений (например, 10), форматирует их в список диалога и прикрепляет к текущему запросу.
      • Продвинутый уровень: Если история слишком длинная, этот пайплайн обрезает старые сообщения или прогоняет их
      через дешевую LLM для создания краткой выжимки (суммаризации).
  • Пайплайн маршрутизации (Intent Router)
      • Для чего: Определить, что вообще хочет пользователь, чтобы выбрать правильную стратегию поведения.
      • Что делает: Анализирует запрос. Это простой разговор? Вопрос о погоде? Запрос на поиск в интернете? Просьба
      сменить анимацию аватара? В зависимости от этого запрос направляется в разные цепочки обработки.


  ### 2. Этап инструментов (Tooling)

  • Пайплайн внешних инструментов (Tool Use / Web Search)
      • Для чего: Дать ИИ доступ к свежей информации (интернет) или локальным файлам компьютера пользователя.
      • Что делает: Если пользователь спрашивает свежие новости, этот пайплайн: 1) делает скрытый запрос в DuckDuckGo,
      2) парсит текст со страниц, 3) формирует скрытый блок "Найденная информация: ...", который ИИ прочитает перед
      тем, как ответить пользователю.


  ### 3. Этап сборки (Prompt Building)

  • Пайплайн формирования личности (System Prompt Builder)
      • Для чего: Задать рамки поведения Kez AI.
      • Что делает: Собирает финальный пакет данных. Он склеивает "Инструкции для ИИ (ты Kez, помощник, отвечай
      кратко)" + "Текущее время и дата" + "Контекст (история)" + "Результаты поиска (если были)" + "Сообщение
      пользователя". И именно этот "бутерброд" отправляется в OpenAI API.


  ### 4. Этап генерации и UI (Execution & Output)

  • Пайплайн Стриминга (Streaming Pipeline) — Критично для компаньона
      • Для чего: Без него пользователь будет смотреть на застывший экран 5-10 секунд, пока ИИ генерирует весь текст
      целиком.
      • Что делает: Использует параметр stream=True при вызове API. Ответ приходит по одному слову/букве. Этот
      пайплайн "ловит" эти кусочки и пробрасывает их в интерфейс PyQt6, создавая эффект того, что Kez "печатает"
      сообщение прямо сейчас.
  • Пайплайн Постобработки и Сохранения (Post-processing)
      • Для чего: Закончить цикл обработки и обновить систему.
      • Что делает:
          1. Форматирует текст от ИИ (например, переводит Markdown из нейросети в формат, понятный QLabel в PyQt).
          2. Извлекает "скрытые команды" ИИ (например, если ИИ захотел сменить эмоцию на видео-аватаре с <idle> на
          <smile>).
          3. Вызывает db.add_message_to_chat() для сохранения сгенерированного ответа в базу данных, чтобы на
          следующем запросе "Пайплайн управления памятью" его увидел.

  системный промпт, доставать 5 последних сообщений из БД и отправлять всё это в API, возвращая финальный текст. А
  уже потом можно будет прикрутить поиск и стриминг!
